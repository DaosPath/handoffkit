# HK-CSP Wire Protocol

## Envelope

Every data and control message uses `MessageEnvelope`. Required fields are
defined by `shared/contracts/schemas/message-envelope.schema.json`.

Core `kind` values:

- `session_open`, `session_ready`, `session_reject`,
- `data`, `ack`, `nack`, `error`,
- `cancel`, `channel_close`, `session_close`,
- `worker_hello`, `worker_heartbeat`, `job_progress`.

Core `payload_type` values include `handoff_state`, `tool_call`, `tool_result`,
`delivery_ack`, `delivery_nack`, `process_error`, `training_job`,
`evaluation_job`, `job_progress`, and `json`.

Implementations must accept unknown `kind` and `payload_type` strings so newer
minor protocol versions can add operations. They may reject an unknown value
when the current process cannot handle it, using a non-retryable NACK.

## Handshake

The initiating peer sends `session_open` with its protocol version and session
configuration. The peer answers `session_ready` or `session_reject`. Data must
not be sent before `session_ready`.

## Framing

- In-process: structured envelope objects.
- stdio: one UTF-8 JSON envelope per line. stdout is protocol-only; logs use
  stderr.
- TCP: four-byte unsigned big-endian payload length followed by UTF-8 JSON.
- WebSocket: one UTF-8 text frame per envelope.

Default maximum encoded frame size is 8 MiB. Binary data and large files use an
`ArtifactRef` carrying URI, digest, size, and media type.

## Ordering and identity

`sequence` is monotonic per channel producer. FIFO is guaranteed per channel and
connection. Reconnection may produce duplicates; consumers use
`idempotency_key` when an operation has side effects.

IDs and timestamps are generated by the runtime, but tests and replay tools may
inject deterministic clocks and ID factories.
