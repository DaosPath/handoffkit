# HandoffKit 1.30-1.39 — App Runtime

> Status: **planned**. No item in this document is an implemented-capability claim.

## Goal

Build an app model on top of the qualified 1.19.5 security baseline and 1.29 browser platform. Apps are installable, permissioned compositions of runtimes, workers, browser capabilities, UI surfaces, and durable jobs.

## Principles

- One canonical app manifest and wire format across runtimes.
- Deny by default; manifests request capabilities but do not grant them.
- Local policy decides grants, isolation, quotas, and data access.
- Lifecycle state is durable and recoverable.
- Studio shows runtime evidence, not desired or mocked state.
- Demos remain outside production packages.

## App bundle

A future app bundle may contain:

- signed manifest and provenance;
- explicit runtime and platform requirements;
- backend workers;
- Browser Core/Lite/Real requests;
- UI panels or routes;
- migrations;
- recipes, templates, and user-facing examples;
- no embedded secret material.

The bundle signature proves origin and integrity. It does not grant permissions.

## Required isolation

The host must enforce:

- process and filesystem boundaries appropriate to the platform;
- network egress policy;
- secret handles rather than raw secret propagation;
- CPU, memory, concurrency, and storage quotas;
- cancellation and deadlines;
- signed update and downgrade rules;
- auditable permission decisions;
- cleanup after uninstall and failed installation.

## Non-goals for this train

- a public marketplace;
- unsandboxed execution of untrusted extensions;
- automatic grants derived only from a manifest;
- claiming container-grade isolation where the OS backend cannot provide it;
- replacing native platform security mechanisms with application-level flags.
