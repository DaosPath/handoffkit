# HandoffKit 1.21 — Generalist always-on agents

Status: **planned**. Nothing in this file is evidence that a capability exists.
It follows the 1.20 Browser Platform release and precedes the 1.30–1.39 App
Runtime train.

## Goal

Let users build **generalist, always-on agents** ("dots") with HandoffKit — the
same category as OpenAI Dots, xAI Grok Bots, and agents built on Meta Muse Spark
— but open, model-agnostic, self-hostable, and auditable:

- any provider HandoffKit already supports (OpenAI, Anthropic, xAI, Meta Model
  API, OpenCode, NVIDIA NIM, Groq, Ollama/local), with fallbacks;
- its own supervised "computer": a per-agent workspace, the tool sandbox, and
  optional Browser Real;
- explicit rules for what the agent may do alone, what needs approval, and what
  is blocked;
- every run leaves a trace, handoffs, and a replayable report.

Generalist only: no vertical (medical, legal, financial) agents ship in core.

## Context (as of 2026-10)

- OpenAI announced Dots (always-on agents with their own cloud computer, rules
  for autonomous / approval / blocked actions) at DevDay on 2026-09-29, and is
  winding down Agent Builder on 2026-11-30 in favour of the Agents SDK and
  ChatGPT workspace agents. HandoffKit does not target the Agent Builder format.
- xAI Grok Bot (beta since 2026-08-11) adds templates, team bots, and creator
  rewards, but is tied to xAI models and documents a shared computer across bots.
- Meta exposes Muse Spark through the Meta Model API for building agents.

## Scope

### 1. Agent spec (cross-runtime contract)

A canonical `AgentSpec`, snake_case on the wire, with Python and JavaScript
parity and golden vectors under `shared/contracts/`:

- `name`, `instructions`, `version`;
- `model`: provider + model + ordered fallbacks + generation settings;
- `tools`: allowlist of built-in tools and MCP servers;
- `rules`: per tool/action `allow` | `approve` | `deny` (default `approve` for
  mutating actions, `deny` for anything unlisted);
- `memory`: scope (`none` | `agent` | `workspace`) and retention;
- `routines`: triggers (`manual`, cron-style schedule, file/URL change, inbound
  message) each with a task template;
- `browser`: `off` | `lite` | `real` (Real requires an explicit grant);
- `budgets`: tokens, cost, wall-clock per run and per day;
- `outputs`: report files, webhook, or MCP/notification sink.

The spec is designed to become one `kind` inside the 1.30 app manifest without a
wire break.

### 2. Agent host (always-on runtime)

- Long-running local host (Python first, JS parity for the client and spec) that
  runs routines, persists state, and resumes after restart.
- Per-agent isolation that is real and testable in 1.21: separate workspace
  directory, separate Browser Real profile, separate memory store, separate
  credentials scope. Process/container isolation is a 1.32 goal and is not
  claimed here.
- Approvals inbox: actions that hit an `approve` rule pause the run until a
  human approves or rejects; rejections are recorded in the trace.
- Budgets enforced before and after each provider call (reuse the existing
  budget/deadline machinery).
- Every run produces `RunTrace`, handoffs, and a JSON/Markdown report.

### 3. Interfaces

- CLI: `handoffkit agent create|list|run|logs|approve|reject|pause|resume|delete`
  and `handoffkit agent new --template <name>`.
- Studio: Agents panel — create from template, rules editor, approvals queue,
  run timeline, budget usage. Empty/error states only from real host data.

### 4. Generalist templates

Shipped as plain specs, all provider-agnostic: research assistant (web research
with citations), daily brief (scheduled sources → summary), writer/editor,
code reviewer, web monitor (watch URLs, report changes), inbox triage via MCP.

## Also in 1.21 (cleanup carried from the 1.20 release)

- **Demo commands:** consolidate the ~19 `demo-*` commands and `showcase` into
  `handoffkit demo <name>` and `handoffkit demo list`. Old commands remain as
  hidden aliases that emit a deprecation notice (per
  [`DEPRECATION.md`](../python/DEPRECATION.md)).
- **Labs extra:** move the research-only and vertical code — `handoffkit.clinical`,
  `handoffkit.crypto_research`, and the doctor / MAI-style medical benchmarks —
  into an optional `handoffkit[labs]` distribution so the core package stays
  generalist. The 1.20 wheel already excludes clinical and crypto_research.

## Also in 1.21 (hardening found during the 1.20 release)

1. **Agent evaluations.** An eval harness for agents built with `AgentSpec`:
   task success, cost, latency, and **rule adherence** (no `deny` action
   executed, no `approve` action executed without approval). It also closes the
   1.20 gap where model-answer accuracy was not measured: grounded answers from a
   live provider are scored against the fetched-evidence oracle.
2. **Evidence that cannot rot.** A scheduled (weekly) workflow runs the release
   evidence scripts (grounding live, Browser Real bench, Studio interop and
   accessibility, C++ interop, dependency audit) and fails on a broken script
   path, an expired or soon-to-expire (≤14 days) grounding corpus, or a regressed
   gate. During 1.20 five evidence scripts were broken for weeks after the 1.19.5
   reorganization and the grounding corpus expired unnoticed.
3. **Canary CI.** A scheduled job builds and tests against the newest stable
   Rust/Node/Python/Go and the newest hosted runner images, so toolchain or
   runner changes (e.g. Rust 1.99 lints, the `macos-13` retirement) are caught
   before they break the main CI. Failures open an issue; they never block
   merges by themselves.
4. **C++ browser parity leftovers.** C++ `url_allowed` checks the `http`/`https`
   scheme like JS/Python; C++ redacts `user:pass@` userinfo inside URL strings
   like JS/Python; `mailto:` and other non-HTTP links are never queued for
   fetching in any runtime.
5. **Repository hygiene.**
   - A `.gitattributes` that normalizes line endings (text files LF in the
     index), ending the mixed LF/CRLF churn on Windows, plus reproducible npm
     tarballs: in the 1.20 CI the same pure-JS package hashed differently on
     Windows, Linux, and macOS (checkout line endings and gzip metadata).
   - Publish the Rust `handoffkit-browser-core` crate alongside the other crates.
   - Version the Browser Core wire `contract_version` deliberately (it still
     reads `1.20.0-alpha.1`), with golden vectors updated in all five runtimes
     and a documented compatibility rule for older peers.

## Exit gates (binary, evidence-based)

1. `AgentSpec` golden vectors round-trip in Python and JavaScript.
2. Rules: `deny` blocks, `approve` pauses and resumes on approval, rejection is
   recorded — tested on real tool calls, not mocks.
3. Host restart resumes a paused run and a scheduled routine without
   duplicating side effects (idempotency keys).
4. Two agents cannot read each other's workspace, memory, or browser profile.
5. Budgets stop a run before exceeding tokens/cost/time, with a structured error.
6. Each template runs end-to-end with at least one hosted and one local provider.
7. Studio panel shows only real host data; accessibility audit has zero
   violations at 375/768/1024/1440.
8. `handoffkit demo <name>` covers every former `demo-*` command; aliases warn.
9. `pip install handoffkit` contains no labs code; `pip install handoffkit[labs]`
   restores it.
10. The agent eval harness reports rule adherence on every template, and a live
    provider grounded-answer accuracy score exists (or is reported unavailable
    with the reason — never estimated).
11. The scheduled evidence workflow has a green run and a demonstrated failure
    on an injected broken path and on an expiring corpus.
12. The canary workflow has at least one recorded run on the newest toolchains.
13. C++ scheme check, userinfo redaction, and non-HTTP link handling match the
    JS/Python vectors.
14. `.gitattributes` is in place with a renormalization commit;
    `handoffkit-browser-core` is in the crates publish list; the Browser Core
    `contract_version` is bumped with golden vectors green in all five runtimes.

## Non-goals

- Vertical agents in core (medical, legal, financial).
- Hosting or a cloud service; agents run where the user runs the host.
- A public marketplace or creator rewards (1.40–1.49 extension ecosystem).
- Importing the OpenAI Agent Builder format (being shut down) or claiming
  compatibility with closed agent products.
- Process/container isolation and signed app bundles (1.30–1.39).
- An own web-scale crawler or search index — cancelled permanently (see
  [roadmap README](./README.md#cancelled-permanently)).
- Native messaging channels (WhatsApp, Telegram, Slack) beyond MCP connectors;
  they can follow in a later version.
