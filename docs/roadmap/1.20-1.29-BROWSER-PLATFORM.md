# HandoffKit 1.20-1.29 — Browser Platform

> Status: **planned, with an implemented 1.20 Browser Lite slice on the current development branch**. This document does not claim that Browser Real or the complete 1.20 release is finished.

The implemented slice adds a bounded `web_deep_research` route to JavaScript,
Python, and C++ Browser Lite. It performs provider calls, fetches, and bounded
exploration through the configured transport in the current process, so a user
does not need to open another browser window. It remains Browser Lite: no
Chromium, arbitrary page JavaScript, user cookies, credentials, or visual
session is involved. The route is experimental until the full Core/Fusion,
packaging, and cross-runtime gates below are complete.

## Goal

Turn the current browser helpers into a layered browser platform without forcing every runtime to embed a browser engine and without depending on a single public search provider.

The platform has three products:

| Product | Responsibility | I/O | Intended footprint |
| --- | --- | --- | --- |
| Browser Core | Canonical contracts, policies, capabilities, errors, action model, and wire format | None | Small and browser-safe |
| Browser Lite | HTTP search, fetch, extraction, and provider adapters | HTTP only | Small, replaceable dependencies |
| Browser Real | Controlled browser-engine service: navigation, DOM, JavaScript, accessibility tree, network, downloads, screenshots, crawling, and local indexing | Native engine and HK-CSP | Large, isolated service |

`Browser Real` is a working product name. It means a real maintained engine controlled by HandoffKit, not a new HTML/CSS renderer written by this project.

## Architecture

### Browser Core

Core contains only deterministic, cross-runtime contracts:

- canonical `snake_case` wire models;
- navigation and action requests;
- normalized page, DOM, accessibility, network, and download events;
- capability negotiation;
- origin, network, filesystem, credential, and download policies;
- structured error codes;
- trace and provenance records;
- replay-safe command identifiers and idempotency rules.

Core must not import an HTTP client, launch a process, open a socket, or advertise an engine capability.

### Browser Lite

Lite preserves and hardens the present search/fetch use case:

- pluggable search providers;
- DuckDuckGo- and Wikipedia-style adapters where their terms and interfaces allow it;
- direct URL fetch;
- bounded redirects, body size, decompression, and timeouts;
- content-type validation and safe text extraction;
- robots and rate-limit policy for crawling helpers;
- deterministic fixtures and live-provider tests kept separate;
- no JavaScript execution or claim of full-page rendering.

Provider availability is detected at runtime. A provider name in an enum does not mean it is reachable or supported.

### Browser Real

Real runs as a supervised native service. The first provider is planned around maintained Chromium plus the Chrome DevTools Protocol. Additional maintained engine providers, such as WebKit or CEF, may be added only after equivalent integration and conformance coverage exists.

The service owns:

- engine lifecycle and crash recovery;
- isolated profiles and storage partitions;
- TLS and proxy policy;
- navigation, frames, DOM, JavaScript, and accessibility operations;
- request interception and response metadata;
- downloads, screenshots, PDF output, and trace capture;
- bounded crawl frontier;
- local document store and search index;
- durable session metadata where policy permits it;
- audit records for every privileged action.

Runtime packages are clients of this service over authenticated HK-CSP. This avoids five independent, inconsistent engine embeddings.

## Package plan

| Ecosystem | Core | Lite | Real client/provider |
| --- | --- | --- | --- |
| JavaScript | `@handoffkit/browser-core` | `@handoffkit/browser-lite` | `@handoffkit/browser-real` |
| Python | `handoffkit.browser.core` | `handoffkit.browser.lite` | `handoffkit.browser.real` |
| Rust | `handoffkit-browser-core` | `handoffkit-browser-lite` | native service and client crate |
| Go | `browser/core` | `browser/lite` | service client package |
| C++ | core model target | optional Lite adapter | service client target |

The existing `@handoffkit/browser` and equivalent public imports remain compatibility facades during the migration. They must never silently upgrade a Lite operation into Real or launch a native engine without explicit configuration.

## Meaning of provider independence

HandoffKit can become independent of DuckDuckGo for content that it is authorized to crawl or ingest by providing its own frontier, document store, local index, ranking, and query path.

This does **not** mean HandoffKit will claim complete coverage of the public web. A local index only knows the corpus that was explicitly seeded, discovered, or imported.

## Security gates

No Browser Real release may pass without:

- authenticated and authorized control connections;
- origin and network egress policy, including loopback and private-address controls;
- explicit credential and cookie boundaries;
- per-profile filesystem isolation;
- download quarantine hooks and size limits;
- replay protection on privileged commands;
- audit trails derived from runtime events, never mocks;
- safe cancellation, deadline, and process-tree cleanup;
- dependency and engine patch policy;
- tests proving denied actions stay denied after reconnect and restart.

## UX gates for Browser Inspector

When implementation starts, Studio must use its design system and meet these gates:

- keyboard-complete navigation and visible focus;
- accessible labels and live status announcements;
- clear separation between observed runtime facts and requested actions;
- explicit permission prompts for privileged operations;
- responsive layouts without horizontal overflow;
- reduced-motion support;
- no mock security state or fabricated engine capability.

## Benchmarks and conformance

Measure, with reproducible environments:

- cold and warm engine startup;
- navigation p50/p95/p99;
- DOM and accessibility extraction;
- crawl throughput and frontier memory;
- index ingest and query latency;
- service reconnect and crash recovery;
- per-session memory and descriptor growth;
- cross-runtime command and event conformance.

## Explicit non-goals

- writing a new Blink/WebKit-class renderer;
- bypassing CAPTCHAs, paywalls, anti-bot controls, or access restrictions;
- stealth fingerprint evasion;
- exporting browser credentials outside an authorized profile boundary;
- silently falling back from Real to Lite, or from a local index to a public provider;
- declaring an engine/provider available from configuration alone.
