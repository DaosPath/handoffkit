# Browser Real threat model (1.20)

This document is the in-tree threat model for supervised Chromium. It does not
claim that Security is 9/10. Critical or high findings keep Security blocked.

## Assets

- Isolated Chromium processes and profile directories owned by HandoffKit
- Artifact store (screenshots, PDFs, Markdown, downloads)
- mTLS private keys and the durable replay store
- Session journal (URLs and status only; no cookies)

## Trust boundaries

1. Peer over TCP: untrusted until certificate authentication succeeds.
2. Command payload: untrusted JSON. Capabilities declared by the peer are ignored.
3. Navigated origins: untrusted. DNS answers, redirects, and subresources are
   re-validated against the local policy.
4. Operator browser profiles, cookies, and saved passwords: never in trust.

## Controls

- Mandatory TLS 1.3 + mTLS, including loopback
- Public bind requires an explicit local permission plus TLS/mTLS
- Envelope order: receive → decode → certificate authentication → transport
  replay → local authorization → business dedup → dispatch
- Durable replay in service mode; in-memory replay is tests/in-process only
- Egress: resolve DNS first, reject non-global IPs, pin the validated address
- Downloads: selector required, 50 MiB cap, quarantine, no success without a
  verifiable file
- Peer `profile_dir` is ignored; persistence is `profile_id` under `profileRoot`

## Out of scope

- Personal browser reuse
- Cookie sharing
- CAPTCHA bypass or stealth
- Exactly-once delivery or silent auto-resume after crash

## Residual risk

Until CodeQL, a dependency audit, and a dedicated review are green, Security
stays below 9/10 regardless of unit tests.
