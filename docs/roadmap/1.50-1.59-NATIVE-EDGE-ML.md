# HandoffKit 1.50-1.59 — Native, Edge, and ML

> Status: **planned**. Hardware and accelerator support remains unavailable until detected and integration-tested on that provider.

## Goal

Unify native workers, artifact-backed ML jobs, media workloads, and resource-constrained deployments behind observable lifecycle and scheduling contracts.

## Version train

| Version | Planned milestone | Exit evidence |
| --- | --- | --- |
| 1.50 | Stable native worker ABI and host protocol | C++/Rust host integration, cancellation, ABI compatibility tests |
| 1.51 | Durable artifact and checkpoint service | integrity/signature checks, restart, migration, corruption tests |
| 1.52 | Checkpoint/resume for compute and ML jobs | process kill and device-loss recovery, duplicate-work policy |
| 1.53 | Accelerator provider interface | real provider detection, CPU baseline, unavailable-path errors |

| 1.59 | Native/edge/ML beta | benchmarks, soak, upgrade, thermal and low-memory qualification |

## Worker requirements

All native and ML workers must provide:

- bounded queues and backpressure;
- cancellation and deadlines;
- lifecycle and graceful shutdown;
- progress derived from actual work;
- `ArtifactRef` inputs and outputs;
- ACK/NACK behavior connected to transport;
- structured failures;
- checkpoint and retry semantics;
- CPU/accelerator metadata obtained from the active backend;
- concurrency, leak, and race tests.

## Accelerator rules

- CPU is the portability baseline.
- CUDA, ROCm, DirectML, Metal, Vulkan, or other providers are advertised only when their real backend is loaded and qualified.
- A compile-time enum or optional dependency does not advertise runtime support.
- No silent fallback when policy requires a particular accelerator.
- Provider, driver, device, precision, and memory facts come from the runtime.

## Edge qualification

An edge profile is not complete until tested for:

- ARM64 build and installation;
- low memory and storage pressure;
- interrupted power/process recovery;
- unreliable networking and clock skew;
- certificate and credential rotation;
- offline artifact verification;
- bounded logs and caches;
- upgrade and rollback on representative devices.

## Non-goals for this train

- declaring every accelerator supported through one generic interface;
- publishing benchmark numbers without environment metadata;
- calling a cross-compile an ARM64 runtime validation;
- embedding private models, game assets, or local test corpora in public packages.
