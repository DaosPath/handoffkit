# HandoffKit 1.19.5 massive release plan

Status: **planned**. HandoffKit 1.19 is not yet complete as a public release.

## Mission

Turn the 1.19 development baseline into one coherent, installable release train
for every participating product. Complete the repository reorganization first,
then build every artifact from one immutable commit. Do not add 1.20 browser
features to this train.

## Release definition

1.19.5 is complete when the scoped 1.19 capabilities are either:

- implemented, integrated, tested, and honestly classified; or
- explicitly excluded and reported unavailable without fallback.

It is not complete merely because CI is green.

## P0 closure gates

| Gate | Required outcome |
|---|---|
| Artifact enforcement | Every in-scope external artifact ingestion route uses integrity, signature, producer/signer policy, bounds, and snapshot verification; unrelated routes are explicitly excluded |
| Durable recovery | Supported session/job routes define restart semantics; completed work survives; active work either resumes safely or becomes an explicit interrupted state |
| Runtime security | Python/Node/Go/Rust retain real-socket evidence; C++ OpenSSL TLS 1.3/mTLS, CRL/OCSP response validation, common dispatcher, and shared transcript vector are provider-dependent and tested behind `HANDOFFKIT_WITH_TLS=ON`; OCSP responder fetch remains unavailable and operational transcript qualification remains experimental |
| Revocation and keys | Local revocation/rotation behavior remains tested; C++ file-backed CRL and signed OCSP response validation are provider-dependent native paths; OCSP responder fetch (AIA/HTTP/HTTPS), cross-runtime stores, and global zeroization remain explicitly excluded |
| Browser honesty | Existing browser package remains the current Lite-style HTTP implementation; Browser Real is not claimed in 1.19.5 |
| Studio honesty | Only runtime-emitted events are visible; unconfigured/corrupt sources never produce mock security facts |
| Operations | Resource limits, reconnect, corruption, migration, backup/restore, and upgrade/rollback tests exist for every durable in-scope service |

## Current Working-Tree Evidence

This section records implemented evidence only; it does not change the planned
release status above.

- The Go-to-`cpp-ml` external artifact route now rejects an input gate unless
  hash verification, required Ed25519 signatures, trusted producers, trusted
  signers, and a trust policy are configured. Direct/local consumers outside
  that route remain out of scope.
- Python, Node, Go, and Rust scheduler file stores plus the Go gateway job
  ledger now test validated private backup/restore with bounded atomic
  replacement. Unsupported state versions still fail closed; no in-place
  migration or package upgrade rollback is claimed.
- Studio production loading accepts only all-Go gateway events and rejects
  mixed-runtime sources. The shared fixture and browser smoke remain schema and
  redaction tests; the real provenance evidence is the Go gateway integration.
- Python CI and publish gates now install the built wheel into a clean virtual
  environment and verify import plus metadata version. C++ CI and publish gates
  install the package prefix and build/run the external `consumer_core` against
  `find_package(handoffkit)`. These are packaging smoke gates, not a release
  approval.
- The JavaScript quality gate now packs all eight workspace packages, installs
  them into an isolated offline consumer using only the generated tarballs, and
  verifies public imports plus artifact versions. The local override is only a
  tarball-consumer test harness; it does not imply registry publication.
- C++ shared TLS transcript operational qualification, OCSP responder fetch,
  cross-runtime OS keystores, global zeroization, durable channel/session
  buffers, automatic in-flight resumption, and exactly-once external effects
  remain explicitly unavailable or excluded. C++ scheduler recovery and the
  common dispatcher are implemented only in their scoped/provider-dependent
  paths.

## Repository convergence

Execute [`REPOSITORY-REORGANIZATION.md`](./REPOSITORY-REORGANIZATION.md) as a
source-layout migration. Public artifact names and runtime behavior remain
compatible in 1.19.5.

Required migration properties:

- use history-preserving moves;
- no simultaneous public API redesign;
- temporary path compatibility only where external tooling requires it;
- update CI, publish workflows, docs, examples, scripts, workspace manifests,
  package metadata, code coverage paths, and release tooling;
- prove no package reads files from its old source path after migration;
- delete old path shims only after clean checkout and artifact consumers pass.

## Required release artifacts

- release manifest containing commit, product, version, filename, SHA-256, size,
  supported platform, and status;
- Python wheel/sdist;
- eight npm tarballs;
- six Rust crate packages;
- Go binaries/source checks where distributed;
- C++ source tarball plus checksum and consumer proof;
- cpp-ml CPU artifact and optional CUDA matrix result;
- Studio production build artifact;
- SBOM/provenance or explicit documented exception per ecosystem;
- migration guide from the pre-reorganization tree.

## CI release matrix

- Python 3.10-3.14;
- Node supported LTS plus provider-specific hybrid job;
- Go minimum version plus provider-specific Go version and `-race`;
- Rust MSRV plus current stable;
- C++ Release assertions, sanitizers, install consumer, and cpp-ml gateway;
- Linux x64 and native ARM64; add Windows/macOS gates for artifacts claiming
  those platforms;
- cross-runtime conformance and real-process interoperability;
- package construction and clean installation from built artifacts;
- repository-path audit proving old source paths are not required.

## Version cut sequence

1. Freeze feature work.
2. Complete path migration and compatibility verification.
3. Close or explicitly exclude every P0 capability.
4. Produce affected-product/version manifest.
5. Update versions and lockfiles once.
6. Build and install all artifacts from the release commit.
7. Run final remote CI on that exact commit.
8. Audit secrets, provenance, claims, changelog, and package contents.
9. Request explicit tag/publish authorization.

## Explicit non-goals

- Browser Core/Lite/Real split;
- native browser daemon or local search index;
- app/extension marketplace;
- general multi-region platform;
- changing wire HK-CSP major version;
- claiming production readiness for unavailable or partially integrated paths.
