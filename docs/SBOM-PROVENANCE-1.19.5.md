# HandoffKit 1.19.5 SBOM and provenance statement

Status: explicit documented exception per the 1.19.5 release plan. No
CycloneDX/SPDX document is generated by this train; the statement below is the
documented exception, per product.

| Ecosystem | SBOM/provenance status | Exception note |
|---|---|---|
| Python (`handoffkit`) | exception | Dependency graph is fully declared in `python/packages/handoffkit/pyproject.toml` (single runtime dependency `cryptography>=46,<50` plus dev extras). Build provenance comes from PyPI Trusted Publishing (OIDC) in `publish.yml`. |
| npm (`@handoffkit/*`, 8 packages) | exception | All packages are dependency-free at runtime (zero production dependencies). Lockfile `pnpm-lock.yaml` pins the full dev graph. Provenance via npm Trusted Publishing (OIDC). |
| Rust workspace (6 crates) | exception | Dependencies locked in `rust/Cargo.lock`; crates.io publish would carry its own provenance. Crates are not published in this train unless explicitly authorized. |
| Go (`go/handoffkit`) | exception | Zero external module dependencies (`go.mod` requires nothing outside stdlib). Source distribution is the artifact. |
| C++ (`cpp/packages/handoffkit`) | exception | Source tarball + SHA256 in the release manifest is the supply-chain artifact; Conan/vcpkg overlays declare third-party deps (OpenSSL, nlohmann_json) consumed from system registries. |
| cpp-ml (`cpp/packages/handoffkit-ml`) | exception | Same model as C++ core; CUDA path is optional and provider-gated. |
| Studio (`apps/studio-web`) + Media Studio | exception | Not published to any registry in this train; built from the same release commit with its lockfile. |

## Why an exception instead of generated SBOMs

The 1.19.5 plan allows "SBOM/provenance or explicit documented exception per
ecosystem". Every ecosystem here either (a) has zero or one runtime
dependency fully declared in its manifest and lockfile, and/or (b) publishes
through OIDC-based Trusted Publishing that already provides cryptographic
provenance. Generating CycloneDX/SPDX documents for this train would add no
information beyond those existing artifacts.

## Integrity

SHA-256 for every release artifact is recorded in
`reports/RELEASE_1.19.5_MANIFEST.json` against the release commit.
